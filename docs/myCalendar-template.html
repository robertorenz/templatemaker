myCalendar

A pop-up date picker beside any date field — one month, three, or a whole year on screen, stacked across or down. Drag across the days to sweep out a from/to range and one button fills in two fields. Pure Clarion, in English or Spanish.

Un selector de fechas emergente junto a cualquier campo de fecha: un mes, tres o un año entero en pantalla, en fila o en columna. Arrastra sobre los días para marcar un rango desde/hasta y un solo botón rellena dos campos. Clarion puro, en inglés o español.

OverviewResumen #

Drag myCalendar - Calendar button next to a date entry and point it at that entry. A small calendar icon appears beside the field; pressing it opens a modal calendar already sitting on whatever the field contains, and Accept puts the date back.

Set the same button to a from-and-to range and it serves two fields: the user drags across the days — over as many months as are on screen — and Accept writes the first day into the FROM field and the last into the TO field.

Install & registerInstalar y registrar #

  1. Copy templates/myCalendar/libsrc/win/MyCalendarClass.inc, MyCalendarClass.clw and cal16.ico to a folder on the Clarion redirection path (your app folder, or \clarion12\libsrc\win). The two source files must be ANSI with CRLF line endings.
  2. Copy templates/myCalendar/template/win/myCalendar.tpl into your template folder.
  3. In the IDE: Setup ▸ Template Registry ▸ Register, pick myCalendar.tpl.
  4. Add the global extension myCalendar - Global to the application once (Global Properties ▸ Extensions ▸ Insert) and set the language and defaults there.
  5. Open a window, and from the control-template list drag myCalendar - Calendar button beside a date field next to the entry you want it to fill in.
  6. Set Date field to fill in to that entry. That is the only required prompt.

What it generates

! in ?CalBtn, Accepted

  Cal1.Orient      = myCalendarOrient

  END

One button, two fieldsUn botón, dos campos #

Set Pick to a from-and-to range and the same button serves two entries. Point From date field and To date field at them and you are done.

  IF Cal2.AskRange(LOC:From,LOC:To)                  ! seeds from both, writes both back
    DISPLAY(?LOC:From)
    DISPLAY(?LOC:To)
  END

AskRange opens on the FROM date with both ends already marked, and hands them back the right way round however the user swept them. If only one day ends up picked, both fields get that day — a one-day range, which is what a user who clicked once meant.

Every press starts a fresh range. Putting the mouse down on a day clears whatever was marked before and anchors there, so a second sweep never has to be untangled from the first.

The fields do not have to be on the same window row They only have to be on the same window. A "period" band with FROM at the top and TO at the bottom works exactly the same.

Pon Pick en rango desde/hasta y el mismo botón atiende a dos campos. Apunta From date field y To date field a ellos y ya está.

  IF Cal2.AskRange(LOC:From,LOC:To)                  ! toma ambos y devuelve ambos
    DISPLAY(?LOC:From)
    DISPLAY(?LOC:To)
  END

AskRange abre sobre la fecha DESDE con los dos extremos ya marcados, y los devuelve en el orden correcto sin importar hacia dónde arrastrara el usuario. Si solo queda un día seleccionado, los dos campos reciben ese día: un rango de un solo día, que es lo que quería decir quien hizo un único clic.

Cada pulsación empieza un rango nuevo. Al bajar el ratón sobre un día se borra lo que hubiera marcado y se ancla ahí, así que un segundo barrido nunca hay que desenredarlo del primero.

Los campos no tienen que estar en la misma fila Basta con que estén en la misma ventana. Una banda de «periodo» con DESDE arriba y HASTA abajo funciona exactamente igual.

Already have a button or menu?¿Ya tienes un botón o un menú? #

Use the code template myCalendar - Open the calendar and return a date. Drop it into any embed — a button's Accepted, a menu item, a hot key — and fill in the variable it should read and write. Everything the control template offers is on its prompts too.

It works on plain variables as well as file fields, so it is the way in when the target is not an entry on the window at all:

  ! dropped in ?PrintRange, Accepted
  Cal3.Months      = 3
  Cal3.Orient      = Cal:Across
  Cal3.Language    = myCalendarLanguage
  IF Cal3.AskRange(LOC:PeriodFrom,LOC:PeriodTo)
    DISPLAY(?PeriodText)
  END
It declares its own object The code template is ,PROCEDURE, which lets it own a %DataSection entry of its own (the same trick the shipped ABPOPUP.TPW uses). You do not have to declare anything by hand.

Usa la plantilla de código myCalendar - Open the calendar and return a date. Suéltala en cualquier embed —el Accepted de un botón, un elemento de menú, una tecla rápida— e indica la variable que debe leer y escribir. Tiene los mismos prompts que la plantilla de control.

Funciona igual con variables sueltas que con campos de fichero, así que es la vía cuando el destino no es un campo de la ventana:

  ! puesta en ?PrintRange, Accepted
  Cal3.Months      = 3
  Cal3.Orient      = Cal:Across
  Cal3.Language    = myCalendarLanguage
  IF Cal3.AskRange(LOC:PeriodFrom,LOC:PeriodTo)
    DISPLAY(?PeriodText)
  END
Declara su propio objeto La plantilla de código es ,PROCEDURE, lo que le permite tener su propia entrada en %DataSection (el mismo truco que usa el ABPOPUP.TPW de Clarion). No tienes que declarar nada a mano.

Application defaultsValores de la aplicación #

The global extension myCalendar - Global holds what every calendar in the application starts from. Add it once, in Global Properties ▸ Extensions. It emits five real globals:

myCalendarLanguage   BYTE(1)                              ! 1 = English, 2 = Espanol
myCalendarFirstDay   BYTE(0)                              ! 0 = Sunday, 1 = Monday
myCalendarView       BYTE(1)                              ! months on screen: 1 2 3 6 12
myCalendarOrient     BYTE(0)                              ! 0 = across, 1 = down
myCalendarWeekNo     BYTE(0)                              ! show the week-number gutter

Every button emits Cal1.Months = myCalendarView and so on, unless you set that prompt to something other than Use the application setting — then it emits the literal instead. Change the global and the whole application follows on the next generate.

They are ordinary variables Nothing stops you assigning to them at run time — myCalendarLanguage = Cal:Spanish in your start-up code, driven by the user's own preference, and every calendar opened afterwards is in Spanish.

La extensión global myCalendar - Global guarda el punto de partida de todos los calendarios de la aplicación. Añádela una vez, en Global Properties ▸ Extensions. Genera cinco variables globales reales:

myCalendarLanguage   BYTE(1)                              ! 1 = ingles, 2 = espanol
myCalendarFirstDay   BYTE(0)                              ! 0 = domingo, 1 = lunes
myCalendarView       BYTE(1)                              ! meses en pantalla: 1 2 3 6 12
myCalendarOrient     BYTE(0)                              ! 0 = en fila, 1 = en columna
myCalendarWeekNo     BYTE(0)                              ! mostrar la columna de semanas

Cada botón genera Cal1.Months = myCalendarView y demás, salvo que pongas ese prompt en algo distinto de Use the application setting: entonces genera el literal. Cambia el global y toda la aplicación le sigue en la siguiente generación.

Son variables normales Nada te impide asignarlas en tiempo de ejecución: myCalendarLanguage = Cal:Spanish en el arranque, según la preferencia del usuario, y todos los calendarios que se abran después salen en español.

Remembering the last sessionRecordar la última sesión #

With Remember the view and options between runs ticked (it is, by default) the calendar comes back the way the user left it. Five things are saved:

SavedProperty
How many months were on screenMonths
Across or downOrient
First day of the weekFirstDay
The week-number gutterShowWeekNo
The ring around todayShowToday

They go into the application's own INI file — <exe>.INI, found with GetModuleFileNameA — under a section named after the profile. Leave the profile prompt blank and it is the procedure name, so two windows never tread on each other. Give two buttons the same profile on purpose and they share a view.

! MyApp.INI
[myCalendar_UpdateOrder]
Months=3
Orient=1
FirstDay=1
ShowWeekNo=1
ShowToday=1

Restored values are checked before use: an impossible month count falls back to one month, and an out-of-range first day or orientation falls back to zero. A hand-edited or corrupt INI cannot break the window.

ForgetSettings() removes the section, so the next open starts from the template's defaults again.

Con Remember the view and options between runs marcado (lo está por defecto) el calendario vuelve tal y como lo dejó el usuario. Se guardan cinco cosas:

Se guardaPropiedad

Van al fichero INI de la propia aplicación —<exe>.INI, localizado con GetModuleFileNameA— en una sección con el nombre del perfil. Si dejas el prompt del perfil en blanco, se usa el nombre del procedimiento, así que dos ventanas nunca se pisan. Si le das a propósito el mismo perfil a dos botones, comparten la vista.

! MyApp.INI

Months=3
Orient=1
FirstDay=1
ShowWeekNo=1

Los valores restaurados se comprueban antes de usarlos: un número de meses imposible vuelve a un mes, y un primer día o una orientación fuera de rango vuelven a cero. Un INI corrupto o editado a mano no puede romper la ventana.

ForgetSettings() borra la sección, así que la siguiente apertura parte otra vez de los valores de la plantilla.

Across or downEn fila o en columna #

Two and three months can go either way — across for a wide, short window, or down for a tall, narrow one. Six and twelve simply transpose their grid. The drop next to the view list flips it, and the choice is remembered.

Pick the one that fits the window the button lives on. A form that is already tall has room for down; a wide report-options screen suits across.

The window is only as wide as the calendar

The navigation strip, not the calendar, is what used to set the width: all on one row it wants about three months' worth of space, so a single month opened in a window mostly full of nothing. When the calendar is narrower than that, the strip now wraps onto two rows — arrows, month and year on the first, Today and the two drop lists on the second — and the window closes down on the months:

Dos y tres meses pueden ir de las dos formas: en fila para una ventana ancha y baja, o en columna para una alta y estrecha. Seis y doce simplemente trasponen su rejilla. La lista que hay junto a la de vistas lo cambia, y la elección se recuerda.

Elige la que encaje en la ventana donde vive el botón. Un formulario que ya es alto tiene sitio para en columna; una pantalla ancha de opciones de informe pide en fila.

Dragging a rangeArrastrar un rango #

In range mode the user holds the button down on the first day and sweeps to the last — across weeks, across months, across the whole year if that is the view. The selection follows the mouse live, so what you see while dragging is what you get.

GestureResult
Press on a dayStarts over. Whatever was marked before is cleared and this day becomes the anchor.
Drag, either wayMarks from the anchor to the day under the mouse. Backwards is exactly as good as forwards — the ends are sorted before they are handed back.
ReleaseDone. The range is what you just swept, with nothing left over from last time.
Press without movingOne day — which comes back as a one-day range.
ClearEmpties the selection; Accept then writes zero dates.

The two ends are drawn solid navy with white numbers; the days in between get a light blue wash. The footer counts the days as you go — From 13/07/2026 to 24/07/2026 (12 days).

Days() returns that count, inclusive of both ends, and InSelection(date) answers 0 (no), 1 (an end) or 2 (in between).

En modo rango el usuario mantiene pulsado sobre el primer día y arrastra hasta el último: por semanas, por meses, o por el año entero si esa es la vista. La selección sigue al ratón en vivo, así que lo que se ve mientras se arrastra es lo que queda.

GestoResultado
Pulsar sobre un díaEmpieza de cero. Se borra lo que hubiera marcado y ese día pasa a ser el ancla.
Arrastrar, en cualquier sentidoMarca desde el ancla hasta el día bajo el ratón. Hacia atrás vale igual que hacia delante: los extremos se ordenan antes de devolverlos.
SoltarListo. El rango es lo que acabas de barrer, sin restos de la vez anterior.
Pulsar sin moverUn solo día, que se devuelve como un rango de un día.
LimpiarVacía la selección; Aceptar escribe entonces fechas a cero.

Los dos extremos se dibujan en azul marino sólido con el número en blanco; los días intermedios llevan un fondo azul claro. El pie va contando los días: Del 13/07/2026 al 24/07/2026 (12 días).

Days() devuelve esa cuenta, incluyendo los dos extremos, y InSelection(fecha) responde 0 (no), 1 (un extremo) o 2 (en medio).

Drag performanceRendimiento del arrastre #

Sweeping a range used to repaint the entire canvas on every mouse move. On the full-year view that is around 1,100 drawing calls per step, and it measured 35 ms — slower than the mouse produces events, so the queue backed up and the drag dragged.

It now repaints only the cells whose selection state actually changed. Extending a range by one day touches one or two cells, whatever the view:

ViewFull repaintOnly what changed 
One month1.0 ms / stepunder 0.05 ms 
Three months8.4 ms / step0.05 ms~160×
Full year35.4 ms / step0.4 ms~85×

200 drag steps per view, timed with CLOCK(). The incremental figures are close to the 10 ms resolution of that clock, so read them as an upper bound.

How it works

Three pieces, all public — you get the same benefit if you drive the class from your own window:

CellAt(date,x,y)Where a date's cell is on the canvas: the exact inverse of DateAt. Returns 0 if that day is not one of the months on screen.
DrawDay(win,?image,date)Repaints one day where it sits, leaving everything else alone.
DrawChanged(win,?image,oldFrom,oldTo)The selection has moved from (oldFrom,oldTo) to the current Date1/Date2; repaint only the days that look different, and return how many that was.
  of1 = Cal.Date1                                     ! remember what it looked like
  of2 = Cal.Date2
  Cal.SetRange(anchor,today)                          ! move the selection
  Cal.DrawChanged(MyWindow,?Canvas,of1,of2)           ! and repaint just the difference
Why not write it in C? Because the arithmetic was never the cost. A drag step is a handful of integer operations and then a thousand GDI calls — moving the arithmetic to C would speed up the part that was already free. Making fewer drawing calls is what mattered, and that is a pure-Clarion change.
Provably identical A test renders a range two ways — one full Draw(), versus a shorter range drawn fully and then extended through DrawChanged — screenshots both and compares them pixel by pixel. One month, three months and a full year all come out with zero differing pixels.

Marcar un rango repintaba antes todo el lienzo en cada movimiento del ratón. En la vista de año completo eso son unas 1.100 llamadas de dibujo por paso, y medía 35 ms: más lento de lo que el ratón genera eventos, así que la cola se acumulaba y el arrastre se arrastraba.

Ahora repinta solo las celdas cuyo estado de selección ha cambiado de verdad. Alargar un rango un día toca una o dos celdas, sea cual sea la vista:

VistaRepintado completoSolo lo que cambia 
Un mes1,0 ms / pasomenos de 0,05 ms 
Tres meses8,4 ms / paso0,05 ms~160×
Año completo35,4 ms / paso0,4 ms~85×

200 pasos de arrastre por vista, medidos con CLOCK(). Las cifras incrementales rozan la resolución de 10 ms de ese reloj, así que tómalas como cota superior.

Cómo funciona

Tres piezas, todas públicas: si manejas la clase desde tu propia ventana, tienes la misma ventaja.

CellAt(fecha,x,y)Dónde está la celda de una fecha en el lienzo: el inverso exacto de DateAt. Devuelve 0 si ese día no está en los meses en pantalla.
DrawDay(ven,?imagen,fecha)Repinta un día en su sitio, sin tocar nada más.
DrawChanged(ven,?imagen,desdeViejo,hastaViejo)La selección ha pasado de (desdeViejo,hastaViejo) a los Date1/Date2 actuales; repinta solo los días que se ven distintos y devuelve cuántos fueron.
  of1 = Cal.Date1                                     ! recuerda como estaba
  of2 = Cal.Date2
  Cal.SetRange(ancla,hoy)                             ! mueve la seleccion
  Cal.DrawChanged(MiVentana,?Canvas,of1,of2)          ! y repinta solo la diferencia
¿Por qué no hacerlo en C? Porque el coste nunca estuvo en la aritmética. Un paso de arrastre son unas pocas operaciones enteras y luego mil llamadas GDI: llevar la aritmética a C aceleraría la parte que ya era gratis. Lo que importaba era hacer menos llamadas de dibujo, y eso es un cambio en Clarion puro.
Idéntico, demostrado Una prueba dibuja un rango de dos maneras —un Draw() completo, frente a un rango más corto dibujado entero y luego alargado con DrawChanged—, captura ambas y las compara píxel a píxel. Un mes, tres meses y un año completo salen con cero píxeles distintos.

The week, the limits, the weekendsLa semana, los límites, los fines de semana #

First day of the week

Cal:Sunday or Cal:Monday. It moves the whole grid, not just the heading row, so the columns always line up under the day names.

Week numbers

ShowWeekNo = 1 adds a narrow gutter down the left of every month with the ISO-8601 week number of each row — the week that contains the Thursday, so the turn of the year lands where a European calendar expects it (1 January 2026 is week 1, 4 January 2027 is week 1).

Limits

MinDate and MaxDate grey out everything outside the window and make it deaf to the mouse. Either can be left at zero for "no limit".

  Cal3.MinDate = TODAY()                              ! nothing in the past
  Cal3.MaxDate = TODAY() + 90                         ! and no further than a quarter out

Weekends

NoWeekends = 1 blocks Saturdays and Sundays the same way — a delivery date, a working day, a court date. Weekend numbers are drawn muted whether or not they are blocked, so the shape of the week is always readable.

Blocked days are skipped, not refused A blocked day simply does not respond, and a drag that passes over one keeps going. There is no error message to dismiss.

Primer día de la semana

Cal:Sunday o Cal:Monday. Mueve toda la rejilla, no solo la fila de cabecera, así que las columnas siempre quedan bajo el nombre de su día.

Números de semana

ShowWeekNo = 1 añade una columna estrecha a la izquierda de cada mes con el número de semana ISO-8601 de cada fila: la semana que contiene el jueves, de modo que el cambio de año cae donde lo espera un calendario europeo (el 1 de enero de 2026 es la semana 1, el 4 de enero de 2027 es la semana 1).

Límites

MinDate y MaxDate atenúan todo lo que quede fuera y lo dejan sordo al ratón. Cualquiera de los dos puede quedarse a cero para «sin límite».

  Cal3.MinDate = TODAY()                              ! nada en el pasado
  Cal3.MaxDate = TODAY() + 90                         ! y no mas alla de un trimestre

Fines de semana

NoWeekends = 1 bloquea sábados y domingos de la misma forma: una fecha de entrega, un día laborable, una fecha de juicio. Los números del fin de semana se dibujan atenuados estén bloqueados o no, para que la forma de la semana siempre se lea.

Los días bloqueados se ignoran, no se rechazan Un día bloqueado simplemente no responde, y un arrastre que pasa por encima sigue su camino. No hay ningún mensaje de error que cerrar.

Makeover no tiene claves para una banda de cabecera, así que la banda lee una sección tuya, en el mismo fichero de estilo. Los nombres de las claves siguen a CapeSoft DrawHeader, de modo que una misma sección sirve a los dos:

Driving it from codeDesde tu propio código #

The class is useful without the pop-up at all. Layout() works out the canvas size and Draw() paints into any IMAGE on any window of yours — an always-visible month on a dashboard, say, with your own hit handling through DateAt():

Cal      MyCalendarClass
Wnd  WINDOW('Planner'),AT(,,400,300),SYSTEM,GRAY
       IMAGE,AT(10,10,200,150),USE(?Canvas)
       REGION,AT(10,10,200,150),USE(?Hot),IMM
     END
  CODE
  Cal.Months     = Cal:ThreeMonths
  Cal.Orient     = Cal:Down
  Cal.ShowWeekNo = 1
  Cal.Layout()                                        ! now CanvasW / CanvasH are known
  OPEN(Wnd)
  ?Canvas{PROP:Width}  = Cal.CanvasW                  ! size the image to fit
  ?Canvas{PROP:Height} = Cal.CanvasH
  ?Hot{PROP:Width}     = Cal.CanvasW
  ?Hot{PROP:Height}    = Cal.CanvasH
  Cal.Draw(Wnd,?Canvas)
  ACCEPT
    IF FIELD() = ?Hot AND EVENT() = EVENT:MouseDown
      d = Cal.DateAt(MOUSEX() - ?Canvas{PROP:Xpos},MOUSEY() - ?Canvas{PROP:Ypos})
      IF d AND Cal.Pickable(d)
        Cal.Pick(d)
        Cal.Draw(Wnd,?Canvas)
      END
    END
  END

The date maths stands alone too — AddMonths, DaysInMonth, WeekNumber and DayOfWeek need no window and no object state.

Override Ask It is VIRTUAL. Derive the class and replace the whole window with your own if the shipped one is not the shape you want — everything below it keeps working.

La clase es útil aun sin la ventana emergente. Layout() calcula el tamaño del lienzo y Draw() pinta en cualquier IMAGE de cualquier ventana tuya —un mes siempre visible en un panel, por ejemplo— con tu propio manejo del ratón a través de DateAt():

Cal      MyCalendarClass
Wnd  WINDOW('Agenda'),AT(,,400,300),SYSTEM,GRAY
       IMAGE,AT(10,10,200,150),USE(?Canvas)
       REGION,AT(10,10,200,150),USE(?Hot),IMM
     END
  CODE
  Cal.Months     = Cal:ThreeMonths
  Cal.Orient     = Cal:Down
  Cal.ShowWeekNo = 1
  Cal.Layout()                                        ! ya se conocen CanvasW / CanvasH
  OPEN(Wnd)
  ?Canvas{PROP:Width}  = Cal.CanvasW                  ! ajusta el image al tamano
  ?Canvas{PROP:Height} = Cal.CanvasH
  ?Hot{PROP:Width}     = Cal.CanvasW
  ?Hot{PROP:Height}    = Cal.CanvasH
  Cal.Draw(Wnd,?Canvas)
  ACCEPT
    IF FIELD() = ?Hot AND EVENT() = EVENT:MouseDown
      d = Cal.DateAt(MOUSEX() - ?Canvas{PROP:Xpos},MOUSEY() - ?Canvas{PROP:Ypos})
      IF d AND Cal.Pickable(d)
        Cal.Pick(d)
        Cal.Draw(Wnd,?Canvas)
      END
    END
  END

La aritmética de fechas también vale por sí sola: AddMonths, DaysInMonth, WeekNumber y DayOfWeek no necesitan ventana ni estado del objeto.

Clarion notesNotas de Clarion #

Things worth knowing, most of them learned the hard way while building this:

NoteDetail
The class is MyCalendarClassNot CalendarClass — ABC already has one of those, in ABUTIL.INC. Two classes of the same name reach the linker as Duplicate symbol: TYPE$CALENDARCLASS (and VMT$, VMTP$) even though neither source file mentions the other. Check \clarion12\libsrc\win\*.INC before naming any class of your own.
BOX outlines in the current penBOX(x,y,w,h,fill) fills with fill but draws its border in whatever SETPENCOLOR last set — which, if you do not set it, is left over from the previous thing drawn. Set the pen before every BOX. Cells that borrow a stale pen look fine until something repaints them in a different order, and then the same day comes out with a different edge.
A full repaint is expensiveA year is 12 months × ~30 cells × several drawing calls. Doing that on every EVENT:MouseMove measured 35 ms per step — a 28 fps ceiling that a drag overruns, so the queue backs up and the sweep feels sticky. Repainting only the changed cells is 0.4 ms. See Drag performance.
Dates are daysA Clarion date is days since 28 Dec 1800, so date % 7 is the day of the week with 0 = Sunday. 1 Jan 1801 was a Thursday and its value is 4.
Month length without a tableDATE(m+1,1,y) - DATE(m,1,y). Clarion normalises month 13 to January of the next year, so December needs no special case, and February is right in every leap year including 1900 and 2000.
Two-argument SETTARGETSETTARGET(window,?image) makes 0,0 the image's own top-left, so all the drawing arithmetic is in canvas coordinates.
REGION with IMMReports EVENT:MouseDown, MouseMove and MouseUp. MOUSEX() / MOUSEY() are window-relative in the same dialog units as PROP:Xpos, so subtracting the canvas position gives the exact space Draw() used.
Paint after the window is upDrawing before EVENT:OpenWindow can land on nothing. The class paints once before ACCEPT and again on OpenWindow.
by is reservedLOOP … BY -1 makes by a keyword; a variable of that name will not compile. (This one cost an afternoon.)
Do not name a method FormatIt shadows the built-in FORMAT() inside the class. The date formatter here is called DateText.
ANSI and CRLFAn LF-only .inc produces the baffling Illegal data type: MYCALENDARCLASS at every use site. The shipped files are correct — keep them that way if you edit them.
SHOW() writes in the font colourSETPENCOLOR colours LINE and the edge of a BOX, nothing else. SHOW() uses the window's current font, colour included. SETFONT(0,…) sets that default font without touching existing controls — but pass every argument: an omitted typeface or size falls back to the system font, not the window's. The class does both in one place, Ink().
Do not name a parameter pKeyKEYCODES.CLW declares PKey EQUATE(0050H), the P key, and labels ignore case. A parameter called pKey in a module that includes it gives Label duplicated on the procedure line — one warning per app that compiles the module — and may resolve to the key code. Here it is pKeyC.

Cosas que conviene saber, casi todas aprendidas a base de golpes al construir esto:

NotaDetalle
La clase es MyCalendarClassNo CalendarClass: ABC ya tiene una con ese nombre, en ABUTIL.INC. Dos clases con el mismo nombre llegan al enlazador como Duplicate symbol: TYPE$CALENDARCLASS (y VMT$, VMTP$) aunque ninguno de los dos fuentes mencione al otro. Mira en \clarion12\libsrc\win\*.INC antes de ponerle nombre a una clase tuya.
BOX se perfila con el lápiz actualBOX(x,y,an,al,relleno) rellena con relleno pero dibuja el borde con lo último que fijara SETPENCOLOR, que si no lo pones es lo que dejara el dibujo anterior. Fija el lápiz antes de cada BOX. Una celda que hereda un lápiz viejo parece correcta hasta que algo la repinta en otro orden, y entonces el mismo día sale con un borde distinto.
Un repintado completo cuesta caroUn año son 12 meses × ~30 celdas × varias llamadas de dibujo. Hacerlo en cada EVENT:MouseMove medía 35 ms por paso —un techo de 28 fps que un arrastre desborda, así que la cola se acumula y el barrido se siente pegajoso. Repintar solo las celdas que cambian cuesta 0,4 ms. Ver Rendimiento del arrastre.
Las fechas son díasUna fecha Clarion son días desde el 28 dic 1800, así que fecha % 7 es el día de la semana con 0 = domingo. El 1 ene 1801 fue jueves y su valor es 4.
Días del mes sin tablaDATE(m+1,1,a) - DATE(m,1,a). Clarion normaliza el mes 13 a enero del año siguiente, así que diciembre no necesita caso especial, y febrero sale bien en todos los bisiestos, 1900 y 2000 incluidos.
SETTARGET de dos argumentosSETTARGET(ventana,?imagen) hace que 0,0 sea la esquina del propio image, así que todo el cálculo del dibujo va en coordenadas del lienzo.
REGION con IMMInforma de EVENT:MouseDown, MouseMove y MouseUp. MOUSEX() / MOUSEY() son relativas a la ventana en las mismas unidades de diálogo que PROP:Xpos, así que restando la posición del lienzo se obtiene el espacio exacto que usó Draw().
Pintar con la ventana ya abiertaDibujar antes de EVENT:OpenWindow puede caer en el vacío. La clase pinta una vez antes del ACCEPT y otra en OpenWindow.
by es reservadaLOOP … BY -1 convierte by en palabra clave; una variable con ese nombre no compila. (Esta costó una tarde.)
No llames Format a un métodoTapa la función FORMAT() dentro de la clase. Aquí el formateador de fechas se llama DateText.
ANSI y CRLFUn .inc con solo LF produce el desconcertante Illegal data type: MYCALENDARCLASS en cada uso. Los ficheros que se entregan son correctos: mantenlos así si los editas.
SHOW() escribe con el color de la fuenteSETPENCOLOR colorea LINE y el borde de un BOX, nada más. SHOW() usa la fuente actual de la ventana, color incluido. SETFONT(0,…) fija esa fuente por defecto sin tocar los controles existentes, pero pasa todos los argumentos: una tipografía o un tamaño omitidos vuelven a la fuente del sistema, no a la de la ventana. TroubleshootingSolución de problemas #

SymptomCause and cure
Duplicate symbol: TYPE$CALENDARCLASS
… VMT$CALENDARCLASS, … VMTP$CALENDARCLASS		You are on an older copy where the class was called CalendarClass, which is the name ABC uses in ABUTIL. Take the current MyCalendarClass.inc / .clw, delete the old CalendarClass.* from the redirection path, and rebuild.
Illegal data type: MYCALENDARCLASSMyCalendarClass.inc has LF-only line endings, or is UTF-8. Save it as ANSI with CRLF.
Unknown identifier: myCalendarLanguageThe myCalendar - Global extension is missing. Add it to Global Properties — the button normally pulls it in by itself.
The button has no iconcal16.ico is not on the redirection path at build time. It is compiled into the EXE, so it is only needed then.
Nothing happens when the button is pressedThe Date field to fill in prompt is empty, or in range mode one of the two field prompts is. The template emits nothing until it knows where the answer goes.
Changing the global language does nothingThe button's own Language prompt is set to English or Spanish instead of Use the application setting.
Two buttons share a viewThey are using the same Profile. Give each its own, or leave the prompt blank to take the procedure name.
The calendar opens on today, not on the fieldThe field was empty or zero. That is intended — there is nothing to open on.
The user cannot pick anythingMinDate / MaxDate exclude the whole visible month, or NoWeekends is on and the view is a weekend.
The window is wider than the screenThe full year across is 4 × 3 and wants about 1100 px. Use Down, or a smaller view, on low resolutions.
The calendar ignores the themeThe Style file expression is blank, or returns a file that does not exist at run time (a relative path is relative to the current folder). Check also the Style set: the keys must be in [<set> Window] or [<set> Default].
Green or amber theme, blue calendarNo Band section, so the accent comes from AccentFontColor. Name the section that holds the theme's BarStartColor.
